## 一、编译与环境问题

### 1.1 Cargo Build/Check 失败（sandbox 限制）

**问题**：sandbox 环境中 `link.exe` 无法写入 `%TEMP%`，导致 `cargo check` / `cargo build` 失败。

**影响**：无法在生产环境中验证编译。所有代码变更只能通过语法检查和自测逻辑验证。

**缓解**：
- 本地开发时已验证通过（`cargo build` 成功）
- CI 配置 `.github/workflows/ci.yml` 保留，但未在 sandbox 中测试

**待解决**：无。这是一个 sandbox 环境限制，不是代码问题。

## 二、存储与序列化问题

### 2.1 加密/压缩前端验证

**问题**：`storage/mod.rs` 中已实现压缩（zstd, level 3）和加密（chacha20, argon2 密钥派生），但尚未进行端到端的前端验证。

**状态**：代码已实现，CLI 支持 `--compress` 和 `--encrypt --password <pwd>` 标志，格式版本升级到 0x0002（新增 16 字节 salt 字段）。

**需要验证**：
- 保存加密文件后能否正确加载？
- 保存压缩文件后能否正确加载？
- 加密+压缩组合能否正常工作？
- 向后兼容性：v0x0001 文件能否被正确读取？

### 2.2 可选的加密密钥管理

**问题**：加密后的密钥如何安全存储？当前密码通过 CLI 参数明文传入，不安全。

**可能方案**：
- 环境变量
- 密钥文件
- 系统密钥链（Windows Credential Manager / macOS Keychain）

### 2.3 大文件处理

**问题**：当前实现全量读写，没有流式处理。大 Cluster（>100MB）可能导致内存溢出。

**可能方案**：
- 分块存储
- 惰性加载
- mmap 内存映射

## 三、共享与合并问题

### 3.1 跨 Cluster 引用

**问题**：Cluster A 的节点如何引用 Cluster B 的节点？

**当前状态**：未实现。每个 Cluster 完全独立，无法跨 Cluster 引用。

**可能方案**：
- 引用 ID + 文件路径：`cluster://path/to/file.stz#node_id`
- 共享节点注册表
- 惰性加载

### 3.2 三路合并

**问题**：当前 Merge 是"两路"（源 vs 目标），缺少共同祖先（common ancestor）。

**可能导致**：合并结果不准确，丢失一些变更。

**可能方案**：
- 在 Cluster 元数据中存储父 Cluster 的哈希
- 三路合并算法（类似 Git 的 merge-base）

### 3.3 惰性克隆

**问题**：当前 Clone 是全量深拷贝，O(n) 内存和时间。大 Cluster 克隆成本高。

**可能方案**：
- 写时复制（Copy-on-Write）
- 引用计数
- 共享未修改节点

### 3.5 跨 Cluster diff 性能

**问题**：`Cluster::diff()` 当前使用全量比较，对于大 Cluster（>10000 节点）可能性能不足。

**优化方向**：
- 使用哈希索引加速节点查找
- 分块比较
- 惰性比较（按需计算 diff）

### 3.4 合并时密码验证

**问题**：源 Cluster 有密码时，是否要求验证密码才能合并？当前未实现。

## 四、查询与算法问题

### 4.1 路径查询索引

**问题**：长路径查询（>100 节点）的 BFS 效率可能不足。

**可能方案**：
- 双向 BFS（从起点和终点同时搜索）
- 节点标签索引
- 关系类型索引

### 4.2 Impact 查询的精度

**问题**：当前 impact 查询是简单反向 BFS，没有考虑边类型和深度限制。

**改进方向**：
- 按关系类型过滤
- 最大深度限制
- 加权影响评分

### 4.3 图的一致性检查

**问题**：当前没有机制检测图的一致性（如循环依赖、孤立节点）。

**当前状态**：部分实现 — `GraphEngine::validate()` 和 `Cluster::validate()` 方法已添加，覆盖孤立边检测、外来节点检测、断桥检测、孤立节点警告。

**改进方向**：
- 循环依赖检测（DFS）
- 拓扑排序
- 类型兼容性检查

### 4.4 子图查询的性能边界

**问题**：`GraphEngine::subgraph()` 使用 BFS，在大图（>1000 节点）上深度无限制时可能性能下降。

**当前状态**：已实现，基础测试通过。未进行性能基准测试。

### 4.5 Cluster diff 的 meta 字段处理

**问题**：`Cluster::diff()` 的 `meta` 字段不参与比较，这意味着 meta 的变更不会被 diff 检测到。这是有意设计还是需要改进？

**决策**：当前设计有意 — meta 是元数据，不是图结构的一部分。如果需要检测 meta 变更，应该使用专门的 `meta_diff` 方法。

### 4.6 Niche/SYN/Arrow Map 占位 crate

**问题**：三个 crate 已创建为占位符，但完整实现尚未开始。

**当前状态**：`crates/arrow-map/`、`crates/niche/`、`crates/syn/` 已创建为占位符，编译通过，无功能逻辑。

**下一步**：在引擎核心稳定后，从 niche（语义解释）开始实现。
