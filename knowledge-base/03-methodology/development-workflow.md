# 开发工作流

> Statuz 项目采用的研发方法论，供后续研发代理参考

---

## 一、阶段式开发

项目采用严格的阶段划分，每个阶段有明确的交付物和验收标准。

### 工作流模板

```
1. 规划：撰写计划文档（.trae/documents/）
   - 现状分析
   - 变更清单（具体文件 + 做什么 + 为什么 + 怎么做）
   - 实施顺序
   - 风险缓解
   - 验证方式

2. 确认：用户审阅计划，确认后执行

3. 实施：严格按照计划执行，不偏离、不重新规划、不添加未请求功能

4. 验证：自测通过、边界情况覆盖、无编译错误

5. 交接：记录变更摘要 + 未解决问题 + 下一个代理应该构建什么
```

### 核心原则

- **计划先行**：每个重大变更前先撰写详细计划文档
- **严格遵循**：实施时严格按照计划，不重新规划
- **验证驱动**：self-test 是核心验证机制
- **交接清单**：每个阶段结束时留交接清单

## 二、语言策略

| 上下文 | 语言 | 说明 |
|--------|------|------|
| 代码 | 英文 | 变量名、函数名、注释、commit message |
| 文档 | 中文 | 计划文档、设计讨论、用户沟通 |
| 官网 | 英文 | 面向开发者受众 |

---

## 三、沟通策略

- **用户不提问就不主动解释**：专注于做事，不解释工具机制
- **假设先行**：对于不确定的决策，做出合理假设，标注假设，然后继续执行
- **不创建不必要的文档**：README.md、参考资料、致谢等章节只在用户明确要求时添加

## 五、记忆管理

### 5.1 核心记忆文件

| 文件 | 内容 | 使用方式 |
|------|------|---------|
| `AGENTS.md` | 引擎工作指南 | 每次会话开始时读取 |
| `project_memory.md` | 硬约束 + 工程约定 | 变更前检查是否违反约束 |
| `user_profile.md` | 用户偏好 | 沟通时参考 |
| `knowledge-base/` | 项目知识库 | 理解上下文时参考 |

### 5.2 记忆更新规则

- **用户级信息**（偏好、背景、技术栈）→ 写入 `user_profile.md`
- **项目级信息**（规则、约束、约定）→ 写入 `project_memory.md`
- **会话级记录**（任务、TODO、相关文件）→ 自动记录在 session_memory

### 5.3 记忆读取策略

- 收到新查询时，先快速检查记忆
- 项目范围查询：检查 project_memory 和近期 topics.md
- 用户偏好查询：检查 user_profile.md
