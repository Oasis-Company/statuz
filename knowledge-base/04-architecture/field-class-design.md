> 性质：**正式设计文档**，不是草稿登记册。记录"为什么 field 要有 class"以及 class 具体承载什么约束/公理。

## 0. 一句话定位（防再次跑偏）

**field 的 class 不是分类标签，而是让 field 从"一坨在变的节点排列"升级为"独立于排列、可被握住的存在物"的约束集合。**

写死这条，是为了以后任何实现都不会把 class 退回成 `type: String` 加个枚举。

---

## 1. 为什么 field 要有 class —— 从"可被握住"推出来

剥到底，一个 field 就是一坨节点 + 它们之间的拓扑。这一坨**本身不稳定**：节点增删、边变动，它随时变形成另一坨。

于是出现一个不可回避的问题：

> 怎么"指"这块？怎么说"这块要改"、"这块波及到谁"、"这块连向增长"？
> 不能指着一坨随时在变的节点排列说话。得指一个**不随排列而变的存在物**。

**class 就是这个存在物。**它让 field 从"节点排列的偶然结果"升级成"独立于排列的实体"。class 不是贴名牌——它是 field **之所以能被当成"一块东西"来谈的那个脊梁**。

这与既有裁定（field-lifecycle-decisions §1，方案 C）的关系：**方案 C 回答了 field 从哪来**（发现生成 + 声明定型）；本文件回答**"定型下来的那块，凭什么能作为一个存在物被握住"**——需要 class 承载约束。两者不冲突，后者补前者缺的定义。

### 承接的既有论断

- "Cluster 是信息宇宙的边界" —— class 让 field 作为 Cluster 内的一块，具备"个体身份"。
- "field 是 class 的**实例化**，不是被 class 分类的对象" —— class 定义 field 的**存在形式**（约束、行为、公理），不是从外面贴个类名。

## 2. class 必须能回答的五类问题（消费侧反向推导）

一个能握住 field 的主体（人 / agent / SYN 载子 / 演化机制）必然问出五类问题。**class 的价值 = 让这五类问题有确定答案。**哪一类现状答不出，就是 class 该补的约束/公理。

| # | 消费方问 | 现状能否答 | → class 承载 |
|---|---------|-----------|-------------|
| ① | 这块的门在哪？哪些节点进来/出去 | 能（拓扑边界） | **边界** |
| ② | 里面的节点凭什么待在一起 | 部分能，说不出"为什么是这一块" | **内聚** |
| ③ | 这块现在合法吗 | 不能 | **一致性** |
| ④ | 这块是谁划的、按什么标准划 | 部分能（`decided_by`），缺"用了什么规则" | **裁决** |
| ⑤ | 这块以后怎么变 | 不能 | **演化** |

现行实现（`Field.type_: Option<FieldType>` + `decided_by`/`decided_at`）只覆盖了 ④ 的一半。①②③⑤ 是 class 的系统性缺口。

## 3. class 的最小约束/公理落地 — 四项，每项可证伪

> 原则：**只立项 class 必须承载的最小四项**。多一项就是过度设计。每一项都要能以工程测试"钉死"（见 §5 测试判据）。

### 公理 A · 身份（field 的"是"）
- 每个 field 是带唯一 id 的存在物，**独立于其节点排列**而存在。
- 不变式：删光字段节点，field 仍是同一个 field；再加回来，仍是它。
- 这一条是"可被握住"的根基——排除了 field 退化为节点排列函数。

### 公理 B · 归属（谁在里面）
- 一个节点**正好属于一个** field（field 间依 Cluster 边界不重叠）。
- 不变式：对任意节点，`belongs_to(field)` 确定且唯一；删除 field 时归属按既定策略级联处理。
- 这条挡住"重叠归属"导致的可指性崩溃。

### 公理 C · 内聚（为什么它们是同一块）
- class **不硬规定** field 必须怎么内聚（内聚定义是类型本体，属过度设计）。class 只**暴露**当前 field 的内聚度量（密度/连通性/桥密度），作为"这块成不成立"的证据。
- 该度量即"这块是否是实的一团"的可测信号；也正好承接 SYN 阶段四的证据厚度不确定度——内聚即"成块把握度"的证据。
- 在 statuz 自举图上必须**可观察可分**：明显连通的 field 内聚高，硬拼的内聚低。

### 公理 D · 演变（什么时候它不再是它）
- 给"field 失真/变质"一个**可测信号**（内聚跌破阈值 / 分裂成两个连通分量）。
- 只先捕捉"值得重划"的信号，**不实现重划流程**（重划是后续阶段）。
- 该信号是"项目演化导致 field 失真→需变更/重定型"（field-lifecycle §3 ④）的触发器。

### 三项约束的相互作用
- A 保证 field 有身份；B 保证身份无歧义；C 给身份以"成立"的证据；D 给 A 的"仍是它"加了失效判据。
- A 是语法，B 是边界，C 是语义证据，D 是时间维。

## 4. 刻意不做（防过度设计防线）

| 不做 | 原因 |
|------|------|
| 不建类型本体 / 类型层级 / 类型间关系 | 内聚已在 C，类型间关系是后续，现在做是空中楼阁 |
| 不做类型演化/蜕变机制的完整版 | 只给 D 的"值得重划"信号，不实现重划流程 |
| 不扩类型值结构 | `kind: String` 保持裸；class 的价值长在约束/公理上，不长在标签上 |
| 不实现发现/置信/SYN 集成 | 那些依赖 A–D 先站稳；本文件只抽象"field 成其为一块的骨架" |

## 5. 工程审视 — 四项可行性的真实判据

> 让步陈词：这一段是"空中楼阁的着陆场"。任何一条若在 statuz 自举图上做不到，公理就当拦腰砍掉，不硬撑。

| 公理 | 最小可证伪判据 | 若失败 |
|------|--------------|--------|
| A 身份 | 对 statuz 自身 repo 图，删光某 field 节点再读回，id 与身份不变 | A 不成立→"可被握住"的前提坍塌，整套退回标签 |
| B 归属 | 全图每个节点 `belongs_to` 唯一；删除 field 归属级联正确 | B 失败→重叠归属，可指性崩溃 |
| C 内聚 | 自举图上，明显连通的 field 度量显著高于硬拼的 | C 失败→内聚信号无区分度，SYN 证据厚度失去依据 |
| D 演变 | 注入无关节点使 field 失真，能捕获"值得重划"信号 | D 失败→演化不可测，field 一旦划定即提死 |

**判定口径**：A/B 为硬约束（不成立则设计不成立）；C/D 为软判据（看重合度/区分度，进灰区则记观察、不硬凑）。执行细则见 `paper/field-class-execution-plan.md`。
