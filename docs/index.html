The problem with
project topology

Every project is a graph. But most tools treat it as a pile of files. Here's what breaks.

Impact is invisible

A schema change breaks 3 services. Nobody knows until CI fails.

Dependencies are implicit

Service A depends on B, but B depends on A. Can you see the cycle?

Communication is expensive

Every change means asking Slack: “Who's affected?”

Five queries.
All topology.

Statuz distills project topology into five operations. That's all you need to map, trace, reason, extract, and validate any system.

Supports --compress (zstd, level 3) and --encrypt (chacha20 + argon2) for storage.

traverse

Walk the graph from any node. Follow edges forward or backward. Discover relationships.

// traverse
graph.traverse("api-gateway")
// → ["auth-service", "orchestrator"]

impact

Find the blast radius. If a node changes, what else is affected? Reverse BFS, instant answer.

// impact
graph.impact("payment-service")
// → { affected: 2, blast_radius: ["orchestrator", "transaction-db"] }

path

Shortest path between any two nodes. BFS-powered, no database needed.

// path
graph.path("api-gateway", "db-primary")
// → { length: 2, path: ["api-gateway", "orchestrator", "db-primary"] }

subgraph

Extract a sub-ecosystem from any seed node. BFS extraction with configurable depth and relation filter.

// subgraph
graph.subgraph(["api-gateway"], { depth: 2 })
// → { nodes: [api-gateway, auth, orchestrator, ...],
  //     edges: [...] }

validate

Check the graph for structural consistency. Detect orphan edges, dangling references, and integrity issues.

// validate
graph.validate()
// → { is_valid: true, issues: [] }

Full topology example

Plus: Cluster diff

Compare two clusters side-by-side. Detect added, removed, and changed nodes, edges, and fields. Essential for code review and change audit. 

// diff
cluster.diff(&modified_cluster)
// → { added_nodes: [...], removed_nodes: [...],
//     changed_nodes: [...], ... }

How Statuz works

Four concepts. One engine. Zero overhead.

Cluster — the storage unit

A self-contained, content-addressed graph container. One cluster, one .stz file.

Field — the perspective

A sub-graph within a cluster. Different views for different teams.

Bridge — cross-field communication

Bidirectional edges connecting nodes across fields. No duplication.

Five Queries — all topology

Traverse, impact, path, subgraph, validate. Five operations cover every graph question.

Organizational pathfinding

graph.path("ceo", "junior-dev")
